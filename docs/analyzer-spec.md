# Content Pulse Analyzer — спецификация (v1)

Третий standalone-инструмент семейства Content Pulse. Автоматизирует отчёт, который Маша собрала руками по EKONIKA (maket_cp_metrics_20260508.pptx, 22 слайда, «вау»-эффект подтверждён) — из ручной работы в минуту машинного времени.

## Что делает

Указываешь папку сессии Capture One (+ опционально проект Cardboard) → получаешь отчёт по смене: HTML в тёмной айдентике Content Pulse (интерактивный, для себя) + экспорт в PDF (для клиента/команды).

## Источники данных

**Всё берётся из .cos-файлов сессии C1** (подтверждено ручным отчётом: 4 835 файлов, без отдельной разметки):

- `Exp_Date` — UNIX-таймштамп срабатывания затвора. Базис всех временных метрик.
- `Basic_Rating`, `Color_Tag` — отбор (эти поля пишет наш же Rate Setter — петля инструментов).
- Слайдеры C1 (Exposure, Clarity, Dehaze, Saturation, NR, USM, Crop...) — «что фотограф уже сделал», детект пресета.
- `Camera_Model`, `Camera_Lens`, ISO, Aperture, ShutterSpeed, FocalLength, ICC, WB — footprint техники и распределения.

**Проект Cardboard** (`.cardboard` JSON) — группировка кадров по артикулам: карточка = артикул, слоты → имена файлов, превью для топов из `previews/`.

**Фолбэк без Cardboard-проекта**: кластеризация по паузам (перерыв > N минут = граница артикула). Грубее, но отчёт выходит всегда.

## Ключевое дизайн-решение (из ручного отчёта)

Часы на камере бывают сбиты → НЕ показываем абсолютное время. Все оси — «час 1, час 2... от старта смены». Интервалы и длительности реальные, привязки к МСК нет.

## Единица данных (решение Маши, 06.07)

**Один отчёт = одна смена (съёмочный день). Один cpreport-файл на смену — данные чище.**
Если в сессии несколько дней — Analyzer режет по дням (разрыв > ~6 часов = новая смена) и выдаёт отдельный отчёт на каждый. Объединение нескольких смен в один просмотр — возможность оставить, но НЕ приоритет; сравнение смен — задача будущего Library по папке cpreport-ов. Модель данных НЕ строить вокруг мультисменного кейса EKONIKA — он только техническая сверка парсера (цифры по дням в ручном отчёте есть отдельно).

## Состав отчёта (по слайдам ручного = проверенный вау-набор)

1. **Шапка смены**: кадров всего, чистое время съёмки, артикулов, мин:сек на артикул (min / median / max), кадр/час, артикулов/час.
2. **Сравнение дней** (если смен несколько): все метрики бок о бок + вывод о стабильности темпа.
3. **Таймлайн**: полоса = артикул, пустоты = паузы, шкала от старта дня.
4. **Паузы**: все > 1 мин, топ самых длинных с нейтральными ярлыками («обед / смена сета / кофе-реквизит») — настраиваемый порог; тон «продаёт сложность работы», не «обвиняет в простое».
5. **Footprint техники**: камера/линза/профиль/WB + доля кадров.
6. **Слайдеры C1**: какие применены и на скольких кадрах → детект базового пресета.
7. **Распределения**: диафрагма, ISO, фокусное (бины 5мм).
8. **По каждому дню**: показатели дня + **топ-5 самых ёмких артикулов** с превью, номером карточки, временем съёмки и «на каком часу смены» (+ опционально топ-3 самых быстрых).
9. Отбор: снято vs rating ≥ 1, конверсия отбора, касаний на карточку (если есть Cardboard).
10. **Эффективное vs затраченное время (идея Маши, 06.07)** — главная аналитическая фишка v1:
    - **Затраченное** время артикула — весь интервал работы: кластер кадров между паузами сессии.
    - **Эффективное** — от первого до последнего кадра, попавших в карточку Cardboard (ключевые кадры).
    - **Поисковое** = затраченное − эффективное: «мялись, доснимали в поисках лучшего, классного не вышло».
    - Визуал: **двухслойный таймлайн** — полоса затраченного, поверх отметки/отрезки ключевых кадров; дыры видны глазами.
    - Паттерны положения ключей внутри интервала: «ключ в начале, дальше поиск» / «ключи в конце — долго раскачивались» / «ключи ровно».
    - Сводка по смене: суммарное поисковое время, доля эффективного, топ артикулов по «поиску» (кандидаты на разбор: свет? референс? категория?).
    - Требует Cardboard-проект (без него слой ключей недоступен — только затраченное).

НЕ входит в v1 (платформенное, слайды 16+ ручного отчёта): action_log, клиентские сессии по share-ссылке.

## Форма

- Каркас как у Cardboard: pywebview + Python, один index.html, тёмная айдентика Content Pulse (палитра #131313/#1d1d1b/медь #C9956B, Manrope + IBM Plex Mono, без иконок/эмодзи).
- Лаунчер: выбрать папку сессии → (опц.) выбрать .cardboard → отчёт.
- Экспорт (уточнение Маши 06.07): **PDF** (отчёт для людей) + **CSV** (по-артикульная таблица: артикул/карточка, кадров снято, ключевых, затраченное, эффективное, поисковое, час смены, паузы — сырьё для Excel и будущего Estimator). HTML — рабочий вид внутри приложения.
- Парсер .cos: файлы с NUL-паддингом (см. reference_capture_one_eip) — читать бинарно-устойчиво.
- Дистрибуция по накатанной: репо content-pulse-analyzer, CI с аттестацией, mac+win, самообновление (см. docs/tool-release-pipeline.md).

## Архитектурный принцип семейства (Маша, 06.07): файл — контракт между инструментами

Никаких баз и серверов: каждый инструмент оставляет после себя простой файл, следующий его ест.

- Rate Setter → пишет отбор в `.cos`.
- Cardboard → `.cardboard` (JSON).
- **Analyzer → кроме PDF/CSV сохраняет машинный отчёт смены `<бренд>_<дата>.cpreport.json` в общую папку накоплений** (по умолчанию одна, настраивается). Папка растёт с каждой съёмкой = датасет.
- Следующий инструмент (**Estimator / Library**) читает папку целиком: динамика темпа между съёмками, «обувь vs сумки за полгода», расчёт смет.
- Когда придёт платформа — БД собирается из этих файлов одним импортом.

Обязательные правила формата: поле `schema: 1` в каждом cpreport (новые версии инструментов обязаны читать старые файлы); самоописательное имя файла; всё содержимое CSV-таблицы дублируется в JSON (CSV — для людей/Excel, JSON — для инструментов).
