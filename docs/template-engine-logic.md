# Логика шаблонов карточки в Content Pulse (выжимка из кода)

Источники: `v2/frontend/js/layout.js` (движок v3), `cards.js` (редактор шаблонов, строки 1044+), `state.js` (библиотека, пропорции), `v2/backend/core/domain/card.py` (CardTemplate/SlotDef). Актуально на 05.07.2026.

## 1. Модель данных

**Шаблон:** `{ id, name, hAspect, vAspect, hasHero, slots: [...] }` (+ привязка к бренду при сохранении). `lockRows` из UI упразднён — авторяды работают всегда.

**Слот шаблона (контейнер под фото) — атрибуты:**

- `orient: 'h' | 'v'` — горизонтальный или вертикальный кадр. Единственный обязательный атрибут.
- `weight: 1 | 2` — вес слота. Только ОДИН слот может иметь weight > 1 (при повышении одного остальные сбрасываются). Это legacy-механика героя: сейчас героя определяет `hasHero`, weight остался для совместимости и для «первый слот крупнее».
- `row: number | undefined` — номер ряда в rest-зоне (задаётся редактором при распределении по рядам; если не задан — авторяды).
- В карточке слот дополняется: `file, dataUrl, path` (само фото).

**Ключевой принцип:** слот НИКОГДА не управляет своим размером. Пропорции у слота нет — есть только ориентация. Размер и aspect задаёт layout-ячейка контейнера, слот заполняет её на 100%×100%.

**Пропорции — глобальные на шаблон, не на слот:**

- `hAspect` для всех горизонталей: 3/2, 4/3, 16/9, 5/4;
- `vAspect` для всех вертикалей: 2/3, 3/4, 4/5, 9/16.

**Герой:** `hasHero=true` → героем всегда является slot[0]. `hasHero=false` → героя нет. (Legacy-фолбэк: если hasHero не задан, героем считается слот с максимальным weight.)

## 2. Три режима раскладки (layDetectMode)

Режим определяется автоматически: есть ли герой и какой он ориентации.

### LANDSCAPE — заглавная ВЕРТИКАЛЬ (hasHero=true, slot[0].orient='v')

Герой-вертикаль слева отдельной колонкой, остальные справа.

- CSS Grid: 2 колонки `2fr / 3fr` (герой / rest), gap 4px.
- Hero-колонка получает aspect-ratio героя (vAspect) — она задаёт высоту всей конструкции.
- Rest-колонка — flex-column из рядов `flex:1` (равные доли высоты героя).
- Размеры rest-ячеек считает JS (`layApplySizes`): после рендера читается фактическая высота hero-колонки, из неё вычисляется row_height и ширина каждой ячейки по её AR; px проставляются инлайн. На resize окна пересчёт заново.
- Авторяды rest-зоны: 1 фото → 1 ряд; 2 → 2 (стопка); 3–5 → 2 ряда; 6+ → 3 ряда с overflow: третий ряд не помещается по высоте героя и уезжает в нижнюю зону `.lay-bottom` (grid-row 2) как justified-ряды на всю ширину.

### PORTRAIT — заглавная ГОРИЗОНТАЛЬ (hasHero=true, slot[0].orient='h')

Герой-горизонт сверху на всю ширину карточки.

- Hero-ряд: одна ячейка с inline aspect-ratio = hAspect.
- Все остальные — justified-ряды под ним (см. ниже).

### EQUAL — героя НЕТ (hasHero=false)

Все фото равноправны: просто justified-ряды сверху донизу, структура как rest у portrait.

### Justified-ряды (portrait rest, equal, overflow-низ landscape)

Раскладка в стиле Flickr/Яндекс.Диска (запрос Маши 07.05.2026):

- фото сохраняют натуральные пропорции, БЕЗ кропа;
- ячейки ряда получают `flex-grow ∝ AR` — ряд всегда заполнен по ширине впритык;
- набивка рядов по сумме аспектов: min 1.5, max 4.0 на ряд (иначе ряд слишком высокий/низкий);
- ограничение количества в ряду: max 3 на мобиле, max 5 на десктопе (своя реализация _laySimpleJustified — у flickr-библиотеки этой опции нет);
- последний ряд скейлится вверх до полной ширины;
- единый gap 4px везде.

## 3. Редактор шаблонов (модалка, cpOpenTemplateEditor)

**Инициализация** — приоритет источников: текущая карточка → `proj._template` (шаблон проекта) → `proj.templateId` (из библиотеки) → дефолт (4 вертикали, первая weight 2, hasHero=true).

**Что умеет:**

- счётчики V и H слотов + фактическое число рядов;
- добавить/убрать слот V или H (новый слот идёт в последний ряд);
- порядок слотов — drag-and-drop прямо в живом превью;
- клик по слоту в превью — переключение weight 1↔2 (с сбросом других);
- чекбокс «Заглавное фото» (hasHero) — вкл/выкл героя, героем становится первый слот;
- селекты пропорций: отдельно для горизонталей (3:2, 4:3, 16:9, 5:4) и вертикалей (2:3, 3:4, 4:5, 9:16);
- управление количеством рядов rest-зоны (+/−) с перераспределением слотов по рядам (teDistributeRows); для portrait hero-ряд считается отдельно;
- живое превью — рендерится ТЕМ ЖЕ layout-движком, что и настоящая карточка (te-slot заполняет ячейку 100%×100%); важно: модалку открыть до рендера, иначе layApplySizes получит нулевую высоту;
- имя шаблона + сохранение в библиотеку.

**Важно:** шаблон фиксирует ряды — раскладка на экране = раскладка шаблона.

## 4. Библиотека шаблонов

- Хранение: localStorage (ключ TEMPLATES_LS_KEY); если пусто — засеваются стартеры: «Горизонт + 3 вертикали» (h+v+v+v), «4 вертикали», «6 вертикалей».
- Выбор шаблона — dropdown прямо в тулбаре карточки.
- «Сохранить шаблон» — быстрое сохранение конфигурации ТЕКУЩЕЙ карточки как нового шаблона (имя через prompt; забираются orient/weight слотов, hAspect/vAspect, hasHero, бренд проекта). Одновременно пишется в `proj._template` для персистенции при save/load проекта.
- У проекта: `templateId` (ссылка на библиотеку) и/или `_template` (встроенная копия).

## 5. Создание карточки из шаблона

Card.from_template: слоты копируются из шаблона по порядку `{orient, weight, row}`, пропорции и hasHero наследуются картой (`_hAspect, _vAspect, _hasHero`); фото раскладываются по слотам, дальше карточка может отклоняться от шаблона (+/− слот), редактор при открытии подхватывает её фактическое состояние.

Domain-слой (Python) дополнительно поддерживает `min_photos/max_photos` (гибкий шаблон «от N до M фото») и `label` слота («главное фото», «деталь») — SlotDef.label, в JS-редакторе меток пока нет.

## 6. Бриф для Claude Design: окно шаблонов в CARDBOARD

Этот функционал переносится в standalone-приложение CARDBOARD (Content Pulse). Нужен дизайн модального окна редактора шаблонов — функционал как выше, но лучше.

**Стиль CARDBOARD (обязательно):** палитра «тёмная плёнка» — подложка #131313, панели #1D1D1B, поля #1A1A18, линии #262626/#2A2A28, текст #F2F2F1 / #B2B2B1 / #8C8C8B, meta #6D6D6C; единственный акцент — медь #C9956B (≤5%); primary-кнопка — инверт (#F2F2F1 на #131313). Шрифты: Manrope (UI), IBM Plex Mono (метки, счётчики, eyebrow, UPPERCASE + letter-spacing). Никаких иконок и эмодзи — только текст и графика из самих слотов. Токены: design/brand-cardboard/tokens/.

**Что должно быть в окне (инвентарь):**

1. Библиотека: список шаблонов (свои + стартеры), выбрать / создать новый / дублировать / удалить.
2. Имя шаблона.
3. Живое превью раскладки — главный элемент окна. То, что видишь = то, как ляжет карточка. Слоты кликабельны и таскаются.
4. Добавить слот: вертикаль / горизонталь. Удалить слот.
5. Герой: вкл/выкл «заглавное фото» (героем становится первый слот). Индикация героя в превью.
6. Порядок слотов — drag-and-drop в превью, с внятной индикацией места вставки.
7. Ряды: +/− ряд, перераспределение слотов; для заглавной-горизонтали hero-ряд отдельно.
8. Пропорции: селект для горизонталей (3:2, 4:3, 16:9, 5:4) и для вертикалей (2:3, 3:4, 4:5, 9:16).
9. Имя каждого слота (Фронт / Спинка / Деталь...) — это уже есть в CARDBOARD, в основной проге нет; вписывается прямо в слот превью, видно в пустых слотах карточки, в PDF и списке.
10. Счётчики: V, H, рядов.
11. Сохранить / Закрыть.

**Что в текущем редакторе основной проги плохо (исправить дизайном):**

- Клик по слоту переключает weight — скрытая механика, никто не догадывается. Героя лучше назначать явно.
- Превью зависит от порядка открытия модалки (нулевые размеры) — дизайн не должен требовать хрупкой инициализации.
- Управление рядами (+/− с перераспределением) непрозрачно: не видно, что куда переедет.
- Пропорции глобальные (H и V), но это нигде не объяснено — пользователь ищет пропорцию у слота.
- Нет undo внутри редактора.

**Сценарий использования:** фотограф до/после съёмки за 1-2 минуты собирает шаблон под категорию товара (обувь, одежда, сумки), называет слоты, сохраняет — дальше все карточки проекта создаются одним кликом по этому шаблону.

Референсы окружения: скриншот текущего CARDBOARD и хендофф «CARDBOARD — Финал» (лого, палитра) в проекте дизайн-аудита.
