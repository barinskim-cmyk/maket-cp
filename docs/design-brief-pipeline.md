# ТЗ для Claude Design: пайплайн съёмки и всё вокруг него

Продукт: **Content Pulse** (рабочее имя приложения — Maket CP) — платформа для
визуального продакшена. Фотограф снимает каталог в Capture One, команда и клиент
отбирают и согласовывают фото, ретушёр дорабатывает. Продукт показывает всем
участникам, что происходит со съёмкой на самом деле.

Дизайн-язык уже утверждён (UI-спека «Тёмная плёнка»): Manrope + IBM Plex Mono,
тёмная тема по умолчанию + светлая, разделение светом (бордеры), без теней,
инверт-кнопки, моно-подписи капсом. Токены в конце документа. Нужно
спроектировать в этом языке САМУЮ важную и сейчас самую страшную часть —
**пайплайн и сопутствующие виды**.

## Главный принцип (с чем имеешь дело)

Вся картина строится из ЕДИНОГО ЖУРНАЛА СОБЫТИЙ по фотографиям (append-only).
У фото нет «этапа» — этап выводится из последнего события. Значит, любой экран
пайплайна — это визуализация свёртки журнала. Процесс, который все считают
линейным, на самом деле ветвится: часть фото согласовали, часть вернули,
параллельно шло переименование. Дизайн должен делать это ветвление ЧИТАЕМЫМ,
а не прятать.

Этапы (фиксированный порядок, этапы без фото НЕ показываются):
превью (преотбор) → отбор команды → отбор клиента → цветокоррекция →
комментарии на ретушь → ретушь → согласование ретуши → адаптация к каналам.

## Что нужно спроектировать

### 1. Пайплайн-панель (правая колонка экрана «Проекты»)
- Вертикальный ствол этапов: только этапы с активностью. Состояния:
  пройден (заливка), текущий (половинка/точка-пульс), будущее не рисуем.
- На каждом этапе: имя, счётчик N/M (сколько фото прошло / сколько было),
  для текущего — «N на этапе».
- **Ветки**: параллельные активности (комментирование, переименование) и
  расхождения групп (согласовали 40 / вернули 12) — ответвления от ствола
  с собственными узлами. Ветка может закрыться (вернуться в ствол) или
  быть открытой. Сейчас это SVG-оверлей, который постоянно съезжает —
  в новом дизайне раскладка должна быть потоковая (grid/flex), без
  абсолютного позиционирования по измеренным координатам.
- Клик по пройденному этапу — снапшот состояния на тот момент.

### 2. Дерево развития событий (новый вид, разворачивается из панели)
- Хронологическое дерево: узлы = события по группам фото
  («Клиент согласовал · 40 фото · Лена · 14:02»), рёбра = следование.
- Развилка видна явно: из «Отбор отправлен клиенту · 52» выходят
  «Согласовано · 40» и «Возвращено · 12 · с комментарием».
- Узел кликается → список фото группы + мета события.
- Должно выдерживать 20–60 событий за проект без превращения в кашу
  (сворачивание рутинных цепочек, зум/скролл — на усмотрение дизайна).

### 3. Сопутствующее (в том же языке)
- **История кадра** — модалка: таймлайн одного фото (события журнала).
- **Live-пульс съёмки** — компактная строка-кардиограмма во время съёмки
  (кадры = биения); полноразмерный пульс уже есть на лендинге, нужен
  встраиваемый вариант в панель.
- **Счётчики для клиента** — упрощённый вид пайплайна в share-виде:
  те же этапы, без веток и внутренней кухни.

## Принципы построения (жёсткие)

1. Этап без фото не существует на экране.
2. Ветвление — первоклассный житель, не исключение.
3. Числа всегда сходятся: сумма по этапам = все фото проекта; развилка
   40 + 12 = 52. Дизайн не должен позволять «потерять» фото визуально.
4. Каждый узел отвечает на: что произошло, с какой группой, кто, когда.
5. Роли видят одну правду: фотограф — всё, клиент — упрощённо, но без вранья.
6. Никаких теней и координатной магии: свет, бордеры, поток.
