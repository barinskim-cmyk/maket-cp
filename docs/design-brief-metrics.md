# ТЗ для Claude Design: метрики съёмки и прогрессивное раскрытие данных

Продукт: **Content Pulse** — см. основной бриф `design-brief-pipeline.md`
(тот же дизайн-язык, те же токены тем, Manrope + IBM Plex Mono).

## Задача

На лендинге мы обещаем: «Реальный пульс вашей съёмки», KPI (4 835 кадров за
2 дня, 361/час, 64 артикула, 3:25 мин/артикул), кардиограмму смен,
MIN / МЕДИАНА / MAX по артикулам, «три характерных артикула», −40% времени
согласования, −90% ручных статусов. Теперь это надо ПОКАЗЫВАТЬ в продукте.

Ключевой принцип: **данных может не хватать — и это состояние интерфейса,
а не ошибка.** Каждая метрика знает, какие данные ей нужны, и если их нет,
вместо пустоты показывает ОДНО конкретное действие, которое их даст.

## Что спроектировать

### 1. Экран/панель «Метрики съёмки» (внутри проекта)
- KPI-строка: кадров всего · кадров/час · артикулов в финале · мин:сек на
  артикул. Формат как на лендинге: большие лёгкие цифры (Manrope 200),
  моно-подписи капсом.
- Кардиограмма съёмки (та же, что на лендинге: пики = кадры артикула,
  плоско = пауза) — интерактивная: ховер по пику → артикул, время.
- Строка MIN / МЕДИАНА / MAX + «самый ёмкий артикул».
- «Три характерных артикула»: самый долгий / точно в медиану / самый быстрый.
- Метрики процесса: время на этап (SLA), итерации до согласования,
  first-pass rate, доля фото с комментариями.

### 2. Лестница доступности данных (ядро задачи!)
Каждый блок метрик имеет 3 состояния:

**ЕСТЬ ДАННЫЕ** — метрика во всей красе.

**ДАННЫХ ЧАСТИЧНО** — показываем что можем + встроенная плашка-действие:
что сделать, чтобы стало полностью. Примеры формулировок (использовать
этот тон — конкретное действие, без укора):
- «Пульс восстановим из сессии — укажите путь к папке сессии Capture One»
  [кнопка: Указать путь]
- «Времена кадров приблизительные. Привяжите сессию — уточним до секунд»
- «Метрики согласования появятся после первой share-ссылки клиенту»
  [кнопка: Поделиться]

**ДАННЫХ НЕТ** — блок не прячется! Показывает свой «скелет» (силуэт
кардиограммы / прочерки в KPI) + одно действие. Пользователь видит,
ЧТО он получит и ЧТО для этого сделать.

### 3. Карта «метрика → требуемые данные → действие»
(дать дизайнеру логику; связана со сценариями A/B/C сбора данных)

| Метрика | Нужно | Если нет — действие |
|---|---|---|
| Кардиограмма, кадров/час, мин:сек/артикул | времена кадров (сессия или файлы) | «Укажите путь к сессии C1» |
| Кадров всего | превью загружены | «Загрузите превью» |
| Артикулов в финале | связка артикулы↔карточки | «Загрузите чек-лист артикулов» |
| MIN/МЕДИАНА/MAX по артикулам | времена кадров + артикулы | оба действия выше |
| Время согласования, first-pass | события клиента (share) | «Отправьте ссылку клиенту» |
| Ручные статусы −90% | журнал событий (само) | — (копится само) |
| Live-пульс | watcher активен | «Начните съёмку в приложении» |

### 4. Состояния для отрисовки (обязательные)
1. Новый пустой проект: все блоки-скелеты с действиями (это первый экран
   после создания — он ПРОДАЁТ ценность, важнейшее состояние).
2. Только превью загружены (сценарий C): счётчики есть, пульс-скелет
   с «укажите путь к сессии».
3. Сессия привязана (B): всё по съёмке есть, метрики клиента — скелет
   с «отправьте ссылку».
4. Полный набор (A + клиент отработал): всё живое.
5. Live-съёмка: пульс бьётся в реальном времени, счётчик кадров растёт.

### 5. Кросс-проектные метрики: фильтры и настраиваемые вкладки (Маша 03.07)

Метрики смотрятся не только внутри проекта, но и ПО ВСЕМ СВОИМ ПРОЕКТАМ:

- **Фильтры:** период (месяц/квартал/свой), бренд/клиент, статус проекта
  (в работе / сдан), участник (кто снимал/ретушировал). Фильтры комбинируются.
- **Настраиваемые вкладки-пресеты:** пользователь собирает несколько типовых
  вкладок под себя — набор метрик + фильтр, сохранённые с именем.
  Дефолтные пресеты, которые предлагаем из коробки:
  «Скорость съёмки» (кадров/час, мин:сек/артикул, пульсы по проектам),
  «Согласование» (время реакции клиента, first-pass rate, итерации),
  «Ретушь» (сроки, возвраты), «Сравнение проектов» (таблица: проект × ключевые
  метрики). Вкладки можно создавать/переименовывать/удалять; настройка —
  чекбоксы блоков метрик + фильтр.
- **Сравнение:** одна метрика по нескольким проектам рядом (мини-спарки/бары
  в стиле кардиограммы) — «этот каталог сняли быстрее прошлого на 18%».
- Лестница данных действует и тут: проекты без данных в выборке видны
  прочерком со своим действием, не выпадают молча.
- Состояние «один проект»: кросс-вид не прячем — показываем с подписью,
  что сравнение появится со вторым проектом.

## Пример данных

Полный набор — сценарий BrandX из `design-brief-pipeline.md` (тот же журнал).
Для состояния 2 использовать его же, но БЕЗ событий session_* / frame_captured:
из этого дизайнер увидит, какие блоки живые, какие скелеты.

Числа для полного состояния: 4 835 кадров · 2 дня · 361/час · 64 артикула ·
3:25 мин:сек/артикул · MIN 0:47 · МЕДИАНА 2:54 · MAX 17:02 · согласование
1.4 дня · first-pass 77% (40 из 52).

## Принципы

1. Пустое состояние — витрина, а не тупик: скелет + одно действие.
2. Никогда не показывать ложную точность: приблизительные времена помечены
   («≈», моно-бейдж «ОЦЕНКА»), точные — без пометок.
3. Каждое действие из плашки ведёт в существующий флоу (указать путь,
   поделиться, загрузить чек-лист) — ничего нового изобретать не надо.
4. Числа всегда сходятся с пайплайном (те же источники — журнал событий).
5. Тон коротких текстов: конкретный глагол + результат («Укажите путь к
   сессии — восстановим пульс до секунд»), без «упс» и без канцелярита.
