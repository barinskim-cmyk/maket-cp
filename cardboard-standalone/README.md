# Cardboard — вёрстка карточек товара

Standalone-инструмент семейства Content Pulse (как Rate Setter). Локальное desktop-приложение: все данные остаются на компьютере, лишних файлов не создаёт.

## Запуск

**Desktop (основной режим):**
```bash
cd cardboard-standalone && python3 main.py
```
Зависимости (pywebview, Pillow) доустановятся сами при первом запуске.

**Браузер (фолбэк):** открыть `index.html` в Chrome. Отличие: фото встраиваются в файл проекта (миниатюрами), путей нет.

## Что делает

1. **Закидываешь фото** — drag-and-drop, кнопка «Добавить фото», вся папка разом, или слежение за папкой. Фото никуда не копируются: приложение запоминает только пути, миниатюры живут в оперативной памяти.
2. **Собираешь карточки** — по шаблону сетки. Шаблоны редактируемые («Шаблоны...»): название, размер сетки и **имя каждого слота** (например: Фронт / Спинка / Деталь). Имена видны в пустых слотах, на бейджах заполненных, в PDF и в списке. Библиотека шаблонов хранится локально и внутри файла проекта.
3. **Структурируешь доп. контент** — свободные контейнеры: произвольный порядок фото (S/M/L), перестановка перетаскиванием, комментарий.
4. **Выгружаешь:**
   - **PDF** — печатная раскладка (диалог печати → «Сохранить как PDF»);
   - **Список** — CSV (для Excel) + TXT: карточка → слот → файл → **полный путь**.

## Файл проекта

Единственный файл, который создаёт приложение, — `имя.cardboard` (JSON): пути ко всем фото, структура карточек и контейнеров, шаблоны, вся локальная информация о проекте. Первое сохранение — через диалог, дальше перезапись того же файла.

Если фото переехали, при открытии проекта они помечаются «файл не найден» (ничего не теряется — пути видны в подсказке и в списке).

**При закрытии** приложение спрашивает: 1) закрыть ли без сохранения, если есть изменения; 2) удалить ли файл проекта (по желанию — чтобы не оставлять следов после сдачи работы).

## Синхронизация с Capture One (хоткей)

1. В Capture One создать экспорт-рецепт (JPEG, папка, например `~/Pictures/cardboard-inbox`) и назначить хоткей на «Export with recipe».
2. В Cardboard — «Следить за папкой», выбрать её.
3. Выделил фото → хоткей → через 2 секунды фото в панели Cardboard.

## Сборка .app (macOS)

```bash
cd cardboard-standalone
/Library/Frameworks/Python.framework/Versions/3.14/bin/python3 -m PyInstaller Cardboard.spec --noconfirm
open dist/Cardboard.app
```
Иконка: когда появится `design/brand-cardboard/icon.icns` — вписать в `Cardboard.spec` (BUNDLE, `icon=`) и пересобрать.

Нюанс, чтобы не наступать снова: в .app-бандле PyInstaller кладёт данные в Resources и делает симлинк из Frameworks — WKWebView не грузит file:// по симлинку (белое окно). Поэтому `find_frontend()` в main.py делает `.resolve()`. Плюс `private_mode=False` + `storage_path` (~/Library/Application Support/Cardboard), иначе localStorage с шаблонами стирается при каждом запуске.

Самопроверка сборки: `CB_DIAG=1 ./dist/Cardboard.app/Contents/MacOS/Cardboard` — печатает READY/TOPBAR/BRIDGE и выходит.

## Технически

- `main.py` — pywebview-мост: диалоги файлов, миниатюры (Pillow, RAM-кэш, на диск не пишутся), слежение за папкой, сохранение проекта, диалоги при закрытии.
- `index.html` — весь UI, чистый JS без фреймворков. Dual-mode: desktop (пути) / браузер (встраивание).
- Префикс функций: `cb*`. Модель: `App.photos / cards / containers / templates`.
